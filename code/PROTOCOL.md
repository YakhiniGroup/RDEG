# Validation protocol for the linear interval search

Prepared before the validation runs. Seed: 20260925. Current manuscript inputs and reference families remain fixed. The implementation is validated independently of the manuscript analyses.

1. Check the linear sum sweep against every feasible count pair, including the smallest-argmin tie convention. Cover all sorted multisets on {-1,0,1} for original group sizes 1 through 5, every budget through min(group sizes), both endpoints, and batched features. Check operation counts per feature, not just candidate counts.
2. Compare WRS and pooled bounds with the frozen O(k²) implementation and direct SciPy enumeration of the full Hamming ball. Cover all admissible budgets in small balanced/unbalanced matrices; continuous, tied, skewed, constant, missing and two-constant-group inputs. WRS includes resulting groups of size one; pooled includes resulting groups of size two. Every comparison includes k=0 and the original labeling.
3. Independently check exact one-sided WRS permutation p-values on small tied and untied rank vectors by enumerating fixed-size null assignments. No normal approximation is used in this check. This validates the endpoint-candidate reduction; the production WRS API remains the paper's specified normal approximation.
4. Check actual multi-feature batches with different pointer trajectories, input/group permutations and positive affine transformations where representable. Reject out-of-range budgets and nonbinary labels explicitly.
5. On the full current MicMa (104×9532) and variance-selected GSE19188 (91×5000) matrices, compare the new algorithm with O(k²) at every published budget (breast 0–5, lung 0–8), and at each test's maximum admissible budget. Compare full p-value endpoint vectors, BH-adjusted upper endpoints, and all three ERDEG families. Independently enumerate every original and single-flip labeling with SciPy on both full focus matrices. Reconcile archived k=1 selections, breast WRS k=2, and all published budget counts/hits.
6. Numerical acceptance: absolute error at most 5e-13 with relative tolerance 3e-10 for floating endpoints; BH membership must agree exactly at the existing thresholds. Integer/rank sum extrema must agree exactly in combinatorial checks. Record discrepancies and any failures; do not change a tolerance in response to a failure without recording the reason.

Expected deliverables: implementation, proof, pseudocode, validation scripts and machine-readable results, input/code hashes, manuscript-ready proposed subsection, and updated tracker. Runtime benchmarking and manuscript adoption belong to the subsequent timing/integration step (#7); this protocol makes no measured-speedup claim.
